## Failure #01 — Stale closure in PUBG live auto-polling

### Prompt
“Add a 3-second auto-refresh to `PubgMatchTelemetry` so it fetches telemetry for the currently selected squad.”

### Faulty AI-generated pattern

```jsx
useEffect(() => {
  const id = setInterval(() => {
    fetchSquadTelemetry(squadId);
  }, 3000);

  return () => clearInterval(id);
}, []);
```

### Bug
The empty dependency array means the interval callback closes over the initial `squadId`. When the user changes the selected squad, polling can continue to request the old squad. If cleanup is omitted in another version of the generated code, intervals can also accumulate.

### DevTools proof to collect
1. Open Chrome DevTools → Network.
2. Filter requests by the telemetry endpoint.
3. Select one squad, then switch to a different squad in the UI.
4. Inspect request URLs or payloads to verify whether requests use the newly selected squad ID.
5. Capture a screenshot showing the selected squad and the corresponding Network request.

### Engineering fix

```jsx
useEffect(() => {
  if (isPaused) return undefined;

  const id = setInterval(() => {
    fetchSquadTelemetry(squadId);
  }, 3000);

  return () => clearInterval(id);
}, [squadId, isPaused]);
```

Use the real fetch function and state names from the project. If requests can overlap or take a long time, consider an `AbortController` and handle request errors.

## Failure #02 — Redundant derived state and extra render passes

### Prompt
“Add a search box and filter the developer's skill list by the search term.”

### Faulty AI-generated pattern

```jsx
const [searchTerm, setSearchTerm] = useState('');
const [filteredSkills, setFilteredSkills] = useState(skills);

useEffect(() => {
  setFilteredSkills(
    skills.filter((skill) =>
      skill.name.toLowerCase().includes(searchTerm.toLowerCase())
    )
  );
}, [skills, searchTerm]);
```

### Bug
`filteredSkills` can be calculated from `skills` and `searchTerm`. Storing it separately introduces duplicated state and an additional render after the effect runs. This makes the state harder to reason about and can cause stale results if dependencies are incomplete.

### DevTools proof to collect
1. Open React Developer Tools Profiler, if installed.
2. Type into the search field and record the component updates.
3. Compare the behavior with the derived-value implementation below.
4. Capture the Profiler result or a screen recording that truthfully shows the observed extra update.

### Engineering fix

```jsx
const [searchTerm, setSearchTerm] = useState('');

const filteredSkills = skills.filter((skill) =>
  skill.name.toLowerCase().includes(searchTerm.toLowerCase())
);
```

Do not add `useMemo` unless profiling shows that memoization is useful. For a small list, direct calculation is simpler.

## Failure #03 — Missing asynchronous cleanup / stale event listener

### Prompt
“Add a keyboard shortcut that refreshes the current match when the user presses `r`.”

### Faulty AI-generated pattern

```jsx
useEffect(() => {
  window.addEventListener('keydown', () => {
    if (event.key === 'r') {
      refreshMatch(squadId);
    }
  });
}, []);
```

### Bug
The callback references `event` without declaring it as a parameter. The listener is never removed, and an empty dependency array can leave the handler using an outdated `squadId`. Re-running setup without cleanup may register duplicate listeners.

### DevTools proof to collect
1. Open Chrome DevTools → Console and press `r` to check for errors.
2. Switch squads and test whether the shortcut acts on the currently selected squad.
3. Use the Sources event-listener inspection or React Profiler as appropriate to investigate duplicate behavior.
4. Capture the actual console result and test steps; do not fabricate evidence.

### Engineering fix

```jsx
useEffect(() => {
  function handleKeyDown(event) {
    if (event.key.toLowerCase() === 'r') {
      refreshMatch(squadId);
    }
  }

  window.addEventListener('keydown', handleKeyDown);

  return () => {
    window.removeEventListener('keydown', handleKeyDown);
  };
}, [squadId, refreshMatch]);
```

Ensure `refreshMatch` has a stable identity when appropriate, and prevent shortcuts from interfering with typing in input fields if the UI includes them.

## Optional additional failure mode — Countdown drift

A naïve countdown such as `setSeconds((seconds) => seconds - 1)` once per interval can drift when browser tabs are throttled in the background. For a deadline-based countdown, calculate the remaining time from an absolute target timestamp and the current time instead of assuming every interval fires exactly on schedule.
