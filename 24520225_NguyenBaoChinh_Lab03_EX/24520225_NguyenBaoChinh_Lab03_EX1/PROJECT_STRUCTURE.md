## 3. Component Hierarchy and Rendering Flow

The application executes through a deterministic linear component pipeline:

```text
index.html
    │
    ▼
src/main.jsx (createRoot -> StrictMode)
    │
    ▼
src/App.jsx (<main className="page">)
    │
    ▼
src/components/DeveloperCard.jsx (<article className={styles.card} aria-labelledby="dev-heading">)
    │
    ├─► <header className={styles.header}>
    │       ├─► <img> (with onError -> <span className={styles.avatarFallback}>)
    │       └─► <hgroup className={styles.identity}> (<h2 id="dev-heading">, <p>)
    │
    ├─► <dl className={styles.metrics} aria-label="Developer metrics">
    │       └─► {Object.entries(metrics).map} -> <Fragment key={key}> (<dt>, <dd>)
    │
    └─► <section className={styles.skillSection} aria-labelledby="skills-heading">
            ├─► <h3 id="skills-heading">Engineering Skills</h3>
            └─► <ul className={styles.skills} aria-label="Engineering Skills">
                    └─► {skills.map} -> <SkillBadge key={skill.id} name={...} tier={...} />
                                             │
                                             ▼
                                        <li className="skill-badge"> (<span>name</span>, <span>tier</span>)
```

### Rendering Sequence Breakdown:
1. **Host HTML (`index.html`):** The browser loads `index.html`, which contains `<div id="root"></div>` and a `<script type="module" src="/src/main.jsx">` entry tag.
2. **Bootstrap (`src/main.jsx`):** Vite resolves `/src/main.jsx`. `createRoot(document.getElementById('root'))` creates a React 19 concurrent root and renders `<App />` wrapped in `<StrictMode>`. Global styles from `src/index.css` are applied.
3. **Page Shell (`src/App.jsx`):** Renders a semantic `<main className="page">` landmark with a descriptive `<header>` and mounts the `<DeveloperCard />`.
4. **Developer Card (`src/components/DeveloperCard.jsx`):**
   - Evaluates props with robust defaults (`fullName`, `role`, `avatarUrl`, `metrics`, `skills`).
   - Renders the root semantic `<article>` container labelled by `<h2 id="dev-heading">`.
   - Renders the avatar image with explicit `width={64}` and `height={64}`. If an error occurs, `imageFailed` state flips to `true`, rendering initials in an accessible fallback `<span>`.
   - Maps `metrics` entries via `Object.entries(metrics)` into direct `<Fragment key={key}><dt>{key}</dt><dd>{value}</dd></Fragment>` children inside `<dl>`.
   - Renders the skills section containing an accessible `<ul aria-label="Engineering Skills">`.
5. **Skill Badges (`src/components/SkillBadge.jsx`):** For each item in `skills`, renders a `<SkillBadge key={skill.id} name={skill.name} tier={skill.tier} />`, returning a semantic `<li>` styled via `:global(.skill-badge)`.

## 4. Architectural Distinctions

To ensure clarity and maintainability, the codebase maintains strict separation across architectural layers:

1. **Application Entry Point (`src/main.jsx`):**
   - Responsible solely for mounting the virtual DOM to the real DOM (`createRoot`), enabling React strict mode, and importing global styles. Contains no presentation logic.
2. **Main Application Component (`src/App.jsx`):**
   - Serves as the top-level layout orchestrator. Provides the outer page container, accessibility landmarks (`<main>`), and page heading.
3. **Reusable UI Components (`src/components/`):**
   - Pure, self-contained presentation components.
   - `DeveloperCard.jsx`: Encapsulates developer data presentation adhering to the Zero-Div-Soup constraint.
   - `SkillBadge.jsx`: Stateless, reusable list item accepting `name` and `tier` props.
4. **Component-Specific CSS Modules (`DeveloperCard.module.css`):**
   - Encapsulates layout, theme variables, typography, and responsive media queries specific to `DeveloperCard`. Classes are uniquely hashed at build time (e.g. `_card_1x2y3`), preventing global CSS collisions.
5. **Global CSS (`src/index.css`):**
   - Configures font families, root design variables, box-sizing resets, background colors, and the main `.page` centering container. Does not override component styles.
6. **Documentation (`*.md`):**
   - Living architectural documents (`AI_FAILURE_AUDIT.md`, `PROJECT_STRUCTURE.md`, `TASK_DECOMPOSITION.md`) providing verifiable evidence of code quality, failure mitigations, and implementation checklists.
7. **Legacy / Experimental Files:**
   - Standalone assets from prior lab assignments (`mini_react.js`, `app.js`, etc.) retained for course reference and grading continuity.
